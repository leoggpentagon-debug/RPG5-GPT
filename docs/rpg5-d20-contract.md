# RPG5-GPT · детерминированный d20 (v1)

Это контракт **сайта**, не изменение базовых игровых правил `engine_rules.md`.
Ведущая определяет, нужна ли проверка, возможное действие, DC, применимость
навыков/статусов, ситуационную оценку и четыре возможных исхода **до броска**.
Сайт **самостоятельно** выбирает равновероятное натуральное число 1–20 через
`crypto.getRandomValues()` с устранением смещения по модулю и затем
детерминированно считает арифметику. Игрок число не вводит и не выбирает.
Одна ожидающая проверка `check_id` — один бросок: результат сохраняется в
локальном хранилище до отправки и повторно используется при обновлении страницы.
Повторной генерации ради другого результата и записи в Supabase нет.

## Ожидающий план в полном player-visible JSON

В существующий пакет `schema: "rpg5-gpt-packet-v1"` добавить поле:

```json
{
  "mechanics": {
    "pending_d20": {
      "schema": "rpg5-d20-plan-v1",
      "check_id": "example-unique-check-id",
      "action": "Пример действия (не игровое событие)",
      "physical": true,
      "possible": true,
      "base_dc": 12,
      "skill_ids": ["melee_combat"],
      "physical_stat": "agility",
      "situation": {"bonus": 1, "reason": "Обоснованное преимущество"},
      "applicable_statuses": [],
      "consequences": {
        "full_success": "Заранее установленное следствие полного успеха",
        "partial_success": "Заранее установленное следствие частичного успеха",
        "partial_failure": "Заранее установленное следствие частичной неудачи",
        "full_failure": "Заранее установленное следствие полной неудачи"
      }
    }
  }
}
```

Это **фрагмент** игрового пакета, а не самостоятельный пакет. `hero` при этом
содержит подтверждённые из базы `stats`, `skills`, `physical`,
`status_effects` и `carried_weight`, как и раньше.

Для применимого статуса элемент `applicable_statuses` имеет вид:
`{"id":"injury-id","polarity":"negative","severity":"ordinary","dc_adjustment":3,"reason":"Ушиб"}`.
Сайт сверяет ID и подтверждённость с `hero.status_effects`. Степени:
отрицательные `ordinary/heavy/critical`, положительные
`ordinary/strong/exceptional`. Положительные статусы меняют предел,
но не добавляют произвольный бонус и не увеличивают DC.

Особый `overloaded`: если известна **точная** полная масса Оливера 18 < кг ≤ 22,
сайт автоматически применит `-2` к физическому d20, тяжёлый предел штрафов 6 и
снижение действующей Скорости на 2 (минимум 1). При неполном весе он опирается
лишь на явно подтверждённый статус. 22+ кг как нарушение постоянной
переноски (строго больше 22) требует отдельной сверки; никакое значение массы
не придумывается.

Если `mechanics.pending_d20` отсутствует, карточка скрыта. Если план неверный
или не хватает данных, **бросок не выполняется**. При валидном плане сайт
автоматически генерирует число, фиксирует результат локально, отображает его и
пытается передать через Chrome Extension; при сбое доступна повторная отправка
**того же** результата, а не повторный бросок. Старые пакеты работают без изменений.

## Возврат через Chrome Extension

После автоматической генерации натурального числа сайт рассчитывает:
`total = natural + applied_bonus - applied_penalty`, категорию по `total - DC`,
и формирует вместе с уже существующим снимком два блока:

- `[RPG5_SITE_D20_RESULT_V1]` — результат и раскрытые вычисления.
- `[RPG5_SITE_SNAPSHOT_V1]` — видимое состояние из текущего JSON.

Расширение автоматически вставляет подготовленное сообщение в игровой чат.
Отправка Enter по текущей схеме остаётся ручной; игрок не выбирает d20.
Доставка/расчёт **не** вызывает `rpg5.commit_scene`; команда сохранения
по-прежнему только буквальное `сохранить`.
