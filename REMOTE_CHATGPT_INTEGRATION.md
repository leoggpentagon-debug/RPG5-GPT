# RPG5-GPT: удалённое подключение ChatGPT Plus

## Требование проекта

Игрок открывает публичный HTML-интерфейс через GitHub Pages с любого устройства. Все действия выполняются на сайте. Домашний компьютер не должен выступать сервером и не обязан быть включён. Gemini и платный OpenAI API не используются.

## Официальная граница доступности (22.11.2026)

- Sign in with ChatGPT различает вход по аккаунту и разрешение расходовать квоту ChatGPT Plus для Responses API.
- Автоматическая регистрация open-source клиента предназначена для поддерживаемых локальных сценариев; **не предоставляет права** разворачивать произвольный удалённый сайт.
- Для удалённо размещённого веб-приложения необходимо запросить доступ OpenAI и получить зарегистрированный OAuth client ID со соответствующими разрешениями.
- Сайт не может получить ChatGPT OAuth credentials и безопасно вызывать модель только статическим JavaScript.
- Официальные документы: https://developers.openai.com/siwc/website ; https://developers.openai.com/siwc/quickstart ; https://openai.com/form/sign-in-with-chatgpt-interest/ ; https://openai.com/policies/sign-in-with-chatgpt-terms/

## Архитектура после одобрения

```text
GitHub Pages (RPG5-GPT)
  | HTTPS — игровые команды/сессия без OpenAI токенов
  v
Защищённый backend (только авторизованный игрок)
  |-- OAuth Sign in with ChatGPT + PKCE, проверка ID token и granted scopes
  |-- Получение player_observable и адресных данных из приватной rpg5
  |-- Вызов Responses API с разрешённым токеном и квотой игрока
  |-- Проверка ответа и механики по engine_rules.md
  |-- Отдельный безопасный вывод сцен и закрытого режиссёрского контекста
  +-- Контролируемое сохранение через rpg5.commit_scene по протоколу
```

### Предварительный контракт проверки готовности

`GET <gatewayUrl>?op=health`

Пример ответа (только после реальной готовности):

```json
{
  "service": "rpg5-gpt",
  "api_version": 1,
  "auth_ready": true,
  "plan_usage_ready": true
}
```

`auth_ready` означает настроенный допустимый OAuth-механизм. `plan_usage_ready` означает разрешённую серверную интеграцию, **не** успешный вход конкретного игрока. Даже когда флаги true, личный вход и тест модели обязательны. Не подделывать эти поля.

### Безопасность

- Не хранить OpenAI OAuth access/refresh tokens, пароль, cookies ChatGPT или Supabase service_role в репозитории или браузерном JS.
- Не пересылать через HTML полные досье, закрытые планы и секреты NPC. Игрок получает только наблюдаемую проекцию.
- Не давать `anon` и `authenticated` права на приватную `rpg5`; использовать проверенный частный доступ.
- Подтверждать личность, доступ к конкретной кампании и защищать от CSRF/повторов/конкурентных ходов. Не допускать использования подписки другого человека.
- Не сохранять игровые последствия одним текстом модели: проверять механику, принадлежность события и согласованность ревизии.
- Действующий `ТЕХНИЧЕСКИЙ_ПРОТОКОЛ.md` разрешает сохранение канона только по «сохранить». Автосохранение потребует отдельной утверждённой технической правки. Пока не использовать.
- GitHub Pages служит статическим фронтендом; никакие серверные секреты и OAuth client secret не публиковать.

### Другой документированный путь

OpenAI также описывает open-source-клиенты на *собственной self-hosted VM*. Это отдельная архитектура с удалённой виртуальной машиной под личным контролем, а не автоматическая активация коммерческой авторизации для произвольного публичного сайта: https://developers.openai.com/siwc/token-sharing-open-source/self-hosted-vms

## Что сейчас реально сделано

Только фронтенд и тест готовности: пока нет разрешённого OAuth client ID и защищённого сервера, игра не отвечает через GPT. Программы на домашнем компьютере для работы этого интерфейса не требуется.
